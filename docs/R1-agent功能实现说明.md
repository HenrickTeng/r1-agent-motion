# R1-Agent：面向课堂的约束式语言—动作接口

**吴杰民　腾家臻**  
香港科技大学（广州）— 编程猫青少年 AI 教育联合实验室

本文说明已落地的 r1-agent（语音 / 文本指挥 R1 执行白名单动作）如何实现，它在后续教师本机控制台中的位置、切换时的安全策略，以及动作库与多模态交互的后续计划。

---

## 1. 问题与设计选择

课堂需要的是：教师说一句或打一句中文（如「请介绍自己，然后挥右手」），机器人执行可检查、可复现的动作，而不是让大模型在线生成关节轨迹。

系统分为两层：

1. **规划层**（规则匹配或 DeepSeek）只输出动作库中的名字，以及一句符合当前 context 与规则的口头回复；
2. **执行层**把名字映射到已在真机标定过的 `arm_sdk` 关键帧、高层行走 `SetVelocity`、以及 TTS。

大模型不允许输出关节角、`LowCmd`、DDS 话题或任意代码。猜错的上界是选错一个库内动作，而不是发出未知力矩。R1 不接入教学平台公网；教师电脑网线进入 `192.168.123.x`，由本机进程发指令。

```bash
python -m r1_agent --text "请介绍自己，然后挥右手"
python -m r1_agent --listen --hardware
python -m r1_agent --text "校长来了" --scene scenes/classroom
```

`--text` 默认规则规划；`--listen` 默认 DeepSeek（用于从机载 ASR 错字中恢复意图）。真机加 `--hardware`。

## 3. 实现要点

### 3.1 感知：文本或 ASR 终稿

打字整句进入规划器。听一轮订阅 `rt/audio_msg`，等待终稿（约 3 s 无新包），不用中间草稿。听前 TTS「请说」，听后冷却，避免把自身播报再当指令。

### 3.2 规划：名称级、可回退

两种规划器均返回 `(reply, 原子动作列表)`。`reply` 受本次 `--context` / 场景 `context.txt` 与目录规则约束，而不是自由闲聊。

| | 规则规划 | DeepSeek 规划 |
|---|---|---|
| 触发 | 默认 `--text` | `--listen` 或 `--deepseek` |
| 机制 | 别名与组合短语匹配 | 系统提示内嵌全部原子名；只许 JSON：`reply` + `actions` |
| 失败 | 禁止词或未命中则不执行 | 超时或非法 JSON 则回退规则；库外名字则整段拒绝 |

`--scene` 只增加话术、别名与组合，不能新增原子或关节。对话轮次保留角色与任务，直到教师明确更换。

### 3.3 目录与执行

当前内置目录在 `actions.json`：原子为 `speech` / `arm` / `move|turn`，另有课堂组合与禁止表（跳舞、下蹲、奔跑、翻滚等）。问答中的左右是机器人本体左右。

`Executor` 按序执行：TTS、等待、以及同一组内走跑与上肢并行。仿真只记录事件；真机经 `DdsRobot`：

| 通道 | 接口 | 约束 |
|---|---|---|
| 上肢 | `rt/arm_sdk` 预录关键帧 | 腿由内置运控维持；不用已返回 3203 的旧 `SetTaskId` 挥手 |
| 行走 | 高层 loco `SetVelocity` | 须 FSM 811；本固件返回 127 视为已发出 |
| 语音 | AudioClient TTS | 遥控器物理急停始终有效 |

r1-agent 不使用扳手腕课的全身 `rt/lowcmd`。

## 4. 后续工作

### 4.1 教师本机控制台

后期课堂形态是教师电脑本地网页（`127.0.0.1:8765`，不暴露公网）：学生在课程平台拼方块并导出文件，教师用网线打开后在真机上运行。控制台将收齐键盘遥控、手势、校园视觉、图形化编程，并把 **r1-agent、动作模仿、扳手腕门闩** 并入同一页。语音问答并入后仍走本文的规划器与目录，只是入口从独立 CLI 变成选项卡。选项卡只做预览，须再点「开始」才向 R1 发令。

### 4.2 独立上肢动作库（仍基于 `arm_sdk`）

执行侧将增加一套与内置课堂原子分开的**上肢动作库**，底层同样只走 `arm_sdk`，不走 `LowCmd`。关键帧来源有两种：

- 动作模仿：从人体 Pose 录一段，抽成关节关键帧；
- 直接设定：在编辑器里给定手部 / 上肢各关节角度，排成关键帧。

若干关键帧组成**动作组**，由学生或教师自定义命名（例如某同学的「专属挥手」），写入目录后即可被 r1-agent 的语言或文字命令点名调用。规划层仍然只输出名字；执行层播放该动作组的 `arm_sdk` 轨迹。

### 4.3 按 context 回复，以及多模态交互

语言 / 文字命令的 `reply` 将继续按教师设定的 context 与规则生成（身份、场景、是否先说明再做动作），而不是模型自由发挥。

再往后计划接入多模态大模型，并使用 R1 机载摄像头：

- **近距迎宾（已落地控制台选项卡）**：左右目拼图时用 SGBM 深度图取人体框中位数距离；单目退回框高估距。固定在约 0.5–1.8 米做原地手部互动（挥手等），不发行走。0.5 米内先请对方退后，0.3 米内贴脸停手。视觉事件写入与语音问答共用的规划对话，后续 ASR/打字仍只输出白名单动作名。
- **人脸**：本地小模型做人脸识别，将画面中的学生与课前登记绑定；例如对某位同学调用其上传的自定义动作组打招呼；
- **物体**：识别镜头中的物品，再按当前场景 context 决定说话内容与是否调用某个动作组（如校园失物、课堂教具）。

视觉结果只作为规划层的额外条件，最终仍须落到白名单动作名与既定回复规则上，不开放由模型直接写关节。

## 5. 功能切换与关闭时的安全步骤

同一时刻只有一套控制权；切换宁可卡顿，也不让两路指令叠在机器人上。

**切换（含从语音问答切到手势 / 键盘 / 跟臂 / 空闲）**

1. 进入新模式前统一关闭：停摄像头识别循环、清除期望速度、对后端 `stop()`（停步，上肢不再跟新轨迹）。
2. 新模式默认不发令，直到教师再次点「开始」。
3. 若上一功能未点「结束」，仍先停发并提示，而不是两套并行。
4. 「结束」只保证不再下发新指令；已经发出、正在执行的步态或挥手无法用软件撤回。现场以遥控器急停为准。
5. 键盘松键必须停步；网页失联约 0.8 s 同样 `StopMove`。
6. 软件软急停 = 停步 + 锁住当前上肢，不进入官方阻尼。拔网线停不了已下发步态。

**与底层课互斥（扳手腕）**

走跑类功能（含 r1-agent、键盘、手势、跟臂）与调试模式下的 `LowCmd` 扳手腕不能同时开。控制台进入「准备离开走跑」后停掉全部教师台后台：教师用遥控器进调试、跑独立扳手腕程序；结束后 R1 关机再开机、确认站稳走跑，网页点「已重新开机」，才允许再开语音 / 键盘等。网页不能代替进调试，也不能代替开机。

建议顺序：先 probe（不驱电机）→ 单功能「开始」→ 换功能前「结束」或接受自动整段停后台 → 物理急停始终在手。

## 6. 与其它具身接口的边界

| | r1-agent | 动作模仿 | 扳手腕 |
|---|---|---|---|
| 语义 | 语言 → 动作名 | 人体 Pose → 关节 | 力矩 / 刚度体验 |
| 总线 | `arm_sdk` + 高层 loco + TTS | `arm_sdk`（FSM 811） | 全身 `LowCmd` |
| 左右 | 机器人左右 | 自拍：人右手 → 机器人左臂 | 指定右腕轴 |

自定义上肢动作组与模仿录制都归 `arm_sdk` 动作库，由 agent 按名字调用；扳手腕仍隔离在调试模式与复机门闩之后。

## 7. 最小复现

```bash
PYTHONPATH=. python -m r1_agent --text "请介绍自己，然后挥右手"
PYTHONPATH=. python -m r1_agent --listen --hardware
```

预期日志含 `heard` / `reply` / `actions`（如 `self_intro`, `wave_right`），随后 TTS 与挥手。实现主要在 `r1_agent/{cli,planner,catalog,executor,dds_robot}.py` 与 `actions.json`；教师台切换见 `r1_studio/session.py` 的 `set_mode` / `_shutdown_activity`。
